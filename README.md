# Разработка системы генерации дизайна помещения по тексту и плану

[English version](README_EN.md)

Выпускная квалификационная работа Григина Ивана Алексеевича, группа М3432, ИТМО. Научный руководитель: Ефимова Валерия Александровна, к.т.н., доцент ФИТиП.

Проект посвящен автоматической генерации интерьерной 3D-сцены по плану помещения и текстовому описанию пользователя. Система получает геометрию комнаты, интерпретирует требования, расставляет предметы, проверяет ограничения, заменяет абстрактные объекты реальными товарами и экспортирует результат в виде структурированной сцены, Blender-файла, рендеров и сметы.

## Актуальность

Подготовка интерьерных 3D-сцен требует ручной расстановки объектов, подбора моделей, материалов и проверки ограничений. Генераторы изображений дают фотореалистичные картинки, но не создают редактируемую 3D-сцену с размерами и координатами. Онлайн-планировщики работают с настоящими предметами и геометрией помещений, но оставляют расстановку ручной. Исследовательские 3D-генераторы автоматизируют layout, но часто не учитывают одновременно план комнаты, требования пользователя и реальные товары производителей.

Цель работы - сократить время подготовки интерьерных 3D-сцен по плану и текстовому описанию с использованием реальных ассетов от производителей, сохранив качество результата не ниже 6/10 по нормированной оценке визуально-языковой модели.

## Что реализовано

- интерпретация пользовательского описания в структурированную спецификацию комнаты;
- выбор первичного генератора расстановки на основе сравнения DiffuScene, M3DLayout и Infinigen;
- основной режим генерации через Infinigen Indoors;
- быстрый процедурный генератор для спальни, кухни, ванной, туалета и других ограниченных случаев;
- геометрические проверки: границы помещения, коллизии, двери, окна и проходы;
- постобработка сцены: исправление пересечений, добавление недостающих объектов, штор и покрытий;
- подбор реальных товаров и материалов из supplier-каталога;
- генерация недостающих GLB-ассетов по фото товаров через TRELLIS.2;
- экспорт результата в JSON, Blender, рендеры, отчет и смету;
- экспериментальная оценка времени генерации, корректности расстановки и визуального качества.

## Общий план генерации

```text
Геометрия помещения + текстовое описание
    -> интерпретация требований
    -> первичная расстановка Infinigen или процедурным генератором
    -> геометрические проверки и исправление сцены
    -> замена на реальные предметы и материалы
    -> структурированная 3D-сцена, Blender-файл, рендеры и смета
```

На вход подается план помещения с высотой стен, оконными и дверными проемами, а также текстовое описание: тип комнаты, стиль, палитра, обязательные объекты и ограничения.

На выходе формируются:

- структурированное описание сцены;
- Blender-файл;
- изображения сцены с разных ракурсов;
- список подобранных товаров;
- смета с ценами и ссылками на производителей;
- диагностические отчеты по качеству и ограничениям.

## Техническая архитектура

Система реализована как артефактный конвейер. Каждый этап не только передает данные дальше в памяти, но и записывает промежуточные JSON-файлы и отчеты в run-директорию. Это позволяет воспроизводить запуск, сравнивать варианты генерации и отлаживать результат по стадиям: от входного плана до итогового `.blend`.

Центральная точка входа - [src/run_pipeline.py](src/run_pipeline.py). Этот скрипт собирает аргументы запуска, применяет конфигурацию из [src/pipeline_config.py](src/pipeline_config.py), создает run-директории, вызывает генераторы через [src/pipeline_runners.py](src/pipeline_runners.py), нормализует артефакты через [src/pipeline_artifacts.py](src/pipeline_artifacts.py) и последовательно запускает optional-стадии: процедурную генерацию, материалы, supplier-замены, сборку Blender-сцены, рендеры и отчеты.

Упрощенная цепочка данных:

```text
room.json + prompt
  -> room intent / design spec
  -> placement.v1.json
  -> scene.v1.json
  -> repaired scene.v1.json
  -> supplier bindings
  -> supplier_scene.v1.json
  -> scene.blend + renders + reports
```

Главная идея реализации - не смешивать разные уровни представления сцены. `placement.v1` хранит результат расстановки: категории объектов, координаты, размеры и повороты. `scene.v1` объединяет расстановку с геометрией комнаты, материалами и служебными метаданными. `supplier_scene.v1` появляется после замены абстрактных объектов реальными товарами и ассетами.

## Форматы данных

Основные промежуточные форматы:

- `room.json` - входная геометрия: `room.id`, `room.type`, `floor_polygon`, `walls`, `doors`, `windows`, `ceiling_height_m`, система координат.
- `room_intent` / `design_spec` - нормализованное описание требований: тип комнаты, стиль, палитра, плотность, желаемые объекты и ограничения.
- `placement.v1.json` - первичная расстановка без полной сцены: объекты, категории, роли, центры, размеры, повороты и правила размещения.
- `scene.v1.json` - центральный формат конвейера: комната + объекты + позы + размеры + материалы + цели для supplier-подбора.
- `supplier_replacements.summary.json` - выбранные товары, цены, ссылки, причины выбора и альтернативные кандидаты.
- `supplier_scene.v1.json` - сцена после применения supplier-замен, готовая к Blender-сборке.
- `run_manifest.json` - параметры запуска и список полученных артефактов.
- `pipeline_stage_timings.json` - длительность стадий конвейера.
- `build_report.json` - диагностика импорта моделей, масштабов, материалов и сборки Blender-сцены.

Такое разделение нужно для отладки. Если финальная сцена выглядит неверно, можно отдельно проверить, где возникла ошибка: в интерпретации prompt, первичной расстановке, постобработке, supplier-подборе или Blender-сборке.

## Интерпретация пользовательского описания

Свободный prompt преобразуется в унифицированную спецификацию. Например, запрос:

```text
Спальная комната в темно-зеленых тонах с деревянной мебелью с местом для работы
```

преобразуется в JSON с типом комнаты, стилем, плотностью, декоративностью и списком предметов:

```json
{
  "room_type": "Bedroom",
  "style_label": "contemporary",
  "furniture": [
    {"semantic": "Bed", "count": 1, "priority": "required"},
    {"semantic": "Chair", "count": 1, "priority": "desired"},
    {"semantic": "Table", "count": 1, "priority": "desired"},
    {"semantic": "Storage", "count": 2, "priority": "desired"},
    {"semantic": "Rug", "count": 1, "priority": "desired"},
    {"semantic": "Lighting", "count": 2, "priority": "desired"}
  ],
  "style_raw": "dark green tones with wooden furniture",
  "density": "medium",
  "decor_richness": "low"
}
```

Для этого используются LLM через Ollama, в частности `gpt-oss:20b` и `Mistral 7B`, а также эвристическая нормализация.

## Расстановка предметов

Для первичной расстановки были рассмотрены DiffuScene, M3DLayout и Infinigen Indoors. DiffuScene и M3DLayout автоматизируют генерацию, но слабо учитывают реальные границы комнат и дают недостаточную геометрическую корректность для поставленной задачи. Infinigen Indoors лучше работает с ограничениями и экспортирует редактируемую Blender-сцену, поэтому он выбран как основной качественный генератор.

Для сравнения генераторов использовались тепловые карты размещения объектов относительно 3D-FRONT и метрики пространственного сходства, включая расстояние полной вариации и расстояние Дженсена-Шеннона.

## Процедурные генераторы

Infinigen дает качественную первичную сцену, но полный цикл с удаленным запуском и передачей файлов может занимать 15-20 минут для тяжелых сцен. Поэтому реализованы быстрые процедурные генераторы.

Для спальни сначала размещается главный объект - кровать, затем вокруг него добавляются тумбы, шкаф, свет, текстиль и декор. Каждый объект проверяется на выход за границы комнаты, коллизии и блокировку проходов.

Для кухонь реализована отдельная процедурная генерация однорядной кухни вдоль подходящей стены. Алгоритм выбирает стену, выстраивает модули в ряд, проверяет стыки, проходы, открывание техники и отсутствие пересечений. Время процедурной первичной расстановки - до 15 секунд.

## Проверка и исправление сцены

После первичной генерации выполняется постобработка:

- исправление коллизий между объектами;
- добавление недостающих предметов;
- добавление штор;
- замена покрытий пола и стен;
- проверка дверей, окон и проходов;
- процедурная замена сложных малых помещений, например ванных и туалетов.

Этот этап повышает физическую корректность и визуальное качество сцены, а также готовит ее к замене абстрактных объектов на реальные товары.

## Реальные предметы и смета

Собран каталог замен:

- 38 899 карточек товаров из 14 источников;
- более 2 000 моделей от производителей;
- мебель, материалы, цены, ссылки и 3D-ассеты;
- описания товаров дополнены VLM по изображениям.

Подбор товара выполняется по категории, габаритам, стилю, материалу, цвету, цене и наличию 3D-модели. После фильтрации и ранжирования LLM выбирает лучший вариант из top-N кандидатов.

В итоговый отчет входят размеры мебели, фотографии товаров, стоимость предметов, расчет стоимости отделочных материалов и ссылки на оригинальные товары производителей.

## Генерация недостающих ассетов

У многих товаров нет универсальной 3D-модели в подходящем формате. Для таких случаев используется TRELLIS.2: по фотографии и карточке товара генерируется GLB-модель. Сгенерированные ассеты дополнительно оцениваются, потому что один удачный ракурс не гарантирует корректную геометрию, материалы и полноту модели.

## Оценка качества

Минимальный целевой уровень качества - 6/10 по нормированному критерию. Для нормировки VLM оценивает эталонные дизайнерские комнаты и реальные фотографии помещений, после чего сгенерированные сцены сравниваются с этой шкалой.

Критерии оценки:

- соответствие описанию;
- отсутствие пересечений;
- качество замен предметов и материалов;
- полнота покрытия комнаты предметами;
- качество расстановки;
- согласованность стиля;
- уверенность модели;
- общее впечатление.

Эксперимент проводился на 65 комнатах. Для каждой комнаты использовались рендеры с разных ракурсов до и после постобработки.

| Тип комнаты | Кол-во комнат | VLM до исправлений | VLM после исправлений | Среднее время |
| --- | ---: | ---: | ---: | ---: |
| Спальня | 23 | 3.54 ± 0.69 | 5.96 ± 0.85 | 8.03 ± 0.64 мин |
| Кухня | 14 | 2.41 ± 1.13 | 5.97 ± 1.33 | 12.69 ± 3.45 мин |
| Гостиная | 22 | 3.19 ± 0.58 | 6.52 ± 0.76 | 6.79 ± 1.01 мин |
| Ванные | 6 | 2.78 ± 1.00 | 5.81 ± 1.40 | 4.13 ± 0.41 мин |
| Среднее | 65 | 3.14 ± 0.42 | 6.19 ± 0.46 | 7.88 ± 1.13 мин |

После исправления коллизий, добавления предметов, замены материалов и процедурной генерации сложных комнат нормированная оценка выросла примерно на три балла и превысила целевой порог.

## Программно-техническая организация

Основные инструменты:

- Python;
- Blender Python API;
- Infinigen Indoors;
- Ollama;
- `gpt-oss:20b`, `Mistral 7B`;
- Llama 3.2 Vision;
- TRELLIS.2;
- Pytest.

Часть модулей рассчитана на локальный запуск, часть - на удаленные серверы с GPU, потому что Infinigen, VLM-оценка и генерация ассетов требуют значительных вычислительных ресурсов.


## Пример запуска

```bash
python3 src/run_pipeline.py \
  --room data/input/room_rec_small.json \
  --prompt "Светлая современная спальня с рабочим местом" \
  --placer infinigen_clean \
  --modes infinigen_clean \
  --run-dir out/example_bedroom \
  --procedural-rooms auto \
  --procedural-density very_high \
  --supplier-catalog-json supplier_catalog_canonical.json \
  --supplier-selection-modes cheapest,optimal,best_match \
  --build-supplier-blend \
  --validate-supplier-variants \
  --render \
  --keep-blend
```

## Основные артефакты

- `placement.v1.json` - первичная расстановка объектов;
- `scene.v1.json` - структурированная сцена после объединения с комнатой;
- `supplier_scene.v1.json` - сцена после замены на реальные товары;
- `scene.blend` - Blender-сцена;
- `supplier_replacements.summary.json` - выбранные товары, цены, ссылки и причины выбора;
- `build_report.json` - диагностика импорта, масштаба, материалов и ассетов.

Один запуск соответствует одной `run-dir`. Внутри нее сохраняются входные данные, результаты анализа prompt, промежуточные JSON, отчеты проверок, варианты supplier-замен, Blender-файл и рендеры. Поэтому результат можно не только посмотреть, но и воспроизвести или разобрать по стадиям.

## Итог

В работе реализован полный конвейер генерации дизайна помещения по тексту и плану с использованием реальных предметов. Время подготовки сцены сокращено до 5-20 минут вместо ручной работы, занимающей часы или день. Собран каталог товаров от российских производителей, дополненный сгенерированными 3D-моделями, реализована проверка качества и подготовлен экспорт результата для дальнейшей работы. Система внедряется в проект rTIM ИТМО для создания и оценки концепций развития территорий.
